# Prototypes (DRIVE-32)

High-fidelity, clickable HTML/CSS/JS prototypes of the DrivePerf v1 apps. There is **no build step**: open the
`index.html` files straight from disk (`file://`). Nothing loads from the network at runtime except an optional
Google Fonts `@import` in `shared/tokens.css`. Without a connection the pages fall back to the system font stacks.

| Path | What |
|---|---|
| [`index.html`](index.html) | Landing page: links to iOS, Android, web and the catalog, with built-vs-placeholder coverage per platform and work package |
| [`ios/index.html`](ios/index.html) | iOS 26/27 Liquid Glass, iPhone 17 Pro frame (402×874 pt, Dynamic Island) |
| [`android/index.html`](android/index.html) | Android 16 Material 3 Expressive frame (412×915 dp, punch-hole camera, gesture bar) |
| `web/` | driveperf.com pages (S-WEB-*), built separately |
| [`app/`](app/) | **The shared screen engine.** One UX and one screen file per work package, rendered per platform via `data-platform` |
| [`shared/`](shared/) | Design-system runtime, generated by A6 (read-only): `tokens.css` / `tokens.js` (DP_TOKENS), `data.js` (**DP_DATA fixtures**, see `docs/design/system/fixtures.md`), `icons.js` (DP_ICONS), `motion.js` (DP_MOTION) |
| [`tools/`](tools/) | `gen-manifest.mjs`, `check.mjs`, `export.mjs`, `pack.mjs`, `cdp.mjs` (tiny headless-Chrome client), `shot.sh` |

## How it fits together

```
app/core/manifest.js   generated from PRD §4 + screen-map §4–§5 + jira-map "Screens → stories": all 106 app screen IDs,
                       their names, epics, features, PRD states (camelCase), platforms, priority, WP and Jira stories
app/core/registry.js   DP.screen(id, def) registration, manifest lookup, ctx.data fixture helpers
app/core/gate.js       D1 in-drive gate (screen-map §2.2) applied to every navigation
app/core/ui.js         DP_UI: the platform-aware primitives from components.md (bars, buttons, chips, lists, cards,
                       sheets, dialogs, rings, maps, charts, states, system-permission mocks, OS live surfaces)
app/core/shell.js      status bar, Dynamic Island / punch-hole, tab bar + capture accessory / floating toolbar, toasts
app/core/router.js     deep links, back stack, tabs, layered presentations, transitions, ctx, delegated interactions
app/core/app.js        boot, bare mode, the catalog side panel
app/core/app.css       device frames + every component style, scoped by [data-platform] × [data-theme]
app/screens/wp-a…f.js  screen definitions per work package (screen-map §4), each with its own wp-x.css
```

Unbuilt screen IDs render a "Not built yet: S-XXX-NN · name" placeholder taken from the manifest, so every link in the app
works from day one. **Screen authors: read [`app/AUTHORING.md`](app/AUTHORING.md)**. It is the complete contract. The
exemplars are S-NAV-01 and S-HOME-01 (`wp-b.js`) and S-TRP-01 (`wp-c.js`).

## Opening, catalog and deep links

Open `ios/index.html` or `android/index.html`. Press **c** (or the Catalog button) to show the side panel. It lists every
screen grouped by work package with links to each state, plus these switches:
- theme (dark/light)
- text size (default, L, XL)
- reduced motion
- reduce transparency
- entitlement (pro, proMonthly, preview, previewEnding, rideAlong, free)
- trip in progress (drives the D1 gate)
- parked/moving
- Health Check preset

Deep links follow screen-map §2.3:

```
index.html#<SCREEN-ID>[/<state>][?trip=<tripId>&route=<routeId>&car=<vehicleId>&event=<id>&ent=<free|preview|previewEnding|pro|proMonthly|rideAlong>
          &health=<preset>&live=<liveTrip state>&moving=1&capture=<manual|paused|denied>&theme=<dark|light>&text=<l|xl>&rm=1&rt=1]
```

Examples:
- `ios/index.html#S-HOME-01/newStoryCard`
- `android/index.html#S-TRP-01/Lock`
- `ios/index.html#S-TRP-01?trip=t20261020-0740&theme=light`
- `ios/index.html#S-STY-01?live=manual` (gated to S-DRV-01)
- `ios/index.html#S-NAV-01/tabBarMinimisedOnScroll`

Unknown states fall back to `default`. Global params (theme, text, rm, ent, live, …) persist while you navigate. The browser Back
button pops the in-app stack.

**Bare mode:** add `?bare=1` (or `&bare=1` inside the hash) to render only the device screen, edge to edge, at exactly its
CSS size, with no frame or panel. Screenshots use this. `shot=1` also turns all animation off.

## Commands (Node ≥ 22, no npm installs; Chrome at `/Applications/Google Chrome.app`, or set `CHROME=/path`)

```sh
node prototypes/tools/gen-manifest.mjs      # regenerate app/core/manifest.js after PRD / screen-map / jira-map changes
node prototypes/tools/check.mjs             # every screen × state on both platforms: JS errors, render/mount throws,
                                            # unregistered screens, missing PRD states, incomplete specs, overflow
node prototypes/tools/export.mjs            # Jira design artifacts for every story (see below)
node prototypes/tools/pack.mjs              # then pack them into the shared WebP gallery (required before committing)
```

`export.mjs` writes `docs/design/<STORY-KEY>/<ios|android>/` for every Jira story in the manifest and every platform it applies to:
- `screens/<S-ID>.png`: the default state, dark, bare mode. iOS is 402×874 @3 = 1206×2622; Android is 412×915 @2.625.
- `screens/<S-ID>--light.png`, `screens/<S-ID>--<state>.png` for each other state, and `--xl.png` where the PRD lists XL.
- `mockup.html`: a contact sheet of every screen and state in the story, as live iframes into the prototype, with "open interactive" links. `mockup.png` is a screenshot of it.
- `design-spec.md`: generated from each screen's `spec` plus the manifest. It covers states, presentation, entry points and exits, resolved colour, type and layout tokens, components, interactions, motion, accessibility, platform notes, analytics, copy, Free/Pro, fixtures and the §9 checklist.
- `assets/`: the icons the screens use (SVG) and any brand assets they reference.

Flags:
- `--platform ios|android`
- `--wp A..F`
- `--story DRIVE-55[,…]`
- `--screens S-HOME-01,S-TRP-01` renders PNGs only for those screens, but still lists every screen of their stories
- `--no-png` writes the spec and HTML only
- `--no-mockup-png`
- `--all-themes` renders every state in light too
- `--concurrency N` (default 4)

The export is idempotent: reruns overwrite the files for the screens they render.

**Always pack after exporting:** `node prototypes/tools/pack.mjs` (needs `cwebp`; `brew install webp`). The export writes full-size PNGs into every story folder, so a screen shared by five stories is stored five times (about 2 GB). `pack.mjs` stores each image once in `docs/design/screens/<ios|android|web>/<name>.webp`, converts `mockup.png` to `mockup.webp`, and rewrites the links in `design-spec.md` and `mockup.html`. Default-state app screens keep full device resolution. Other states are stored at 2×. `.gitignore` blocks the unpacked PNGs.

`tools/shot.sh` is still available for one-off screenshots.
